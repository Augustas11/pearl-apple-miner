# B9 V0: Pearl FP8 source delta

Compared `25695462416f0eb069abe7a515d188882078bf70` with
`f696760b259500ecb608469ea3953aeabbe78948` (branch `fp8-scheme`,
2026-10-02). The latter is now the detached `vendor/pearl-fp8` pin;
`scripts/fetch_vendor.sh` reproduces it. The old revision remains available in
Git for comparison. The separate v3 `vendor/pearl` pin is unchanged.

## Grid-path decision

**The source delta preserves the grid-path premise.** The following files are
byte-identical between the pins: `api/fp8/{utils,compute,dtype,quantization,noise,
jackpot_policy,prequant}.rs`, `api/layout.rs`, and
`circuit/fp8/unpredictability.rs`, under `zk-pow/src`.

B200 still uses 32-product groups, a 26-bit internal significand, per-term
truncation toward zero, and FP32 round-toward-zero at group boundaries. Its
noise ratio is 0.5, rank is 32, and the quantizer/policy have no new restriction
against constant-magnitude operands. Thus the measured conditional proof still
applies: operands on the 0.5 grid, a carry on the 0.25 grid, and a conservative
bound below 2^22 permit exact FP32 accumulation. Every unproved group still
requires the exact fallback. This is not a proof that every possible noise
draw stays on the grid or that fallback stays below 1% at large k.

## Consensus, parameters, and header chain

PR #355 (`7a505950`) is the material FP8 change. `JobParams.ancestor_header`
(`sigma_d`) is now a **complete 108-byte BlockHeader**, including its proof
commitment, instead of a 76-byte incomplete header. The proposed header remains
76 bytes. `JobParams::check_ancestry` authenticates the selected ancestor by
SHA256d-walking full parent headers from the proposed header's previous hash.
The window contains the most recent four ancestors, excluding the proposed
header. A proof includes zero to three intermediate headers, parent first;
the selected ancestor is in the job/public statement and is not repeated in
that chain.

Source: `zk-pow/src/api/fp8/public_params.rs` (`STATE_WINDOW_DEPTH`,
`JobParams`, `check_ancestry`), `api/primitives.rs` (`BlockHeader`), and
`api/proof_utils.rs` (`BlockHeader::block_hash`). The old caller-side
authentication is replaced by checks inside both plain and ZK verifier entry
points. Missing, reversed, disconnected, excessive, or mutated ancestry must
reject before proof verification.

Common limits are unchanged: k in [1024, 65536], k divisible by 32, rank 32,
E4M3 prequant, device H100 or B200; lottery layout and opening limits are
unchanged. Fork activation parameters and the exact required-version cutover
in `node/chaincfg/params.go` have no delta. Regtest already activates v4 at
height 1; mainnet activation is not newly introduced by this pin.

## Commitments and noise

The labelled transcript retains its structure, but **keyB's input changes**:

```
keyA = H_key-A(proposed_header[76])
keyB = H_key-B(ancestor_header[108])
seedB = H_seed-B(HB || keyB || pB)
seedA = H_seed-A(HA || seedB || keyA || pA)  # dense
```

MoE also binds routing/offset roots into seedA. The ancestor's proof commitment
now affects keyB, B's Merkle trees, seedB, seedA, and the lottery. Old job data
cannot simply be relabelled cert-v4. Use Pearl's transcript and commitment
functions (`api/fp8/transcript.rs`, `api/proof_utils.rs`).

The sampler and normalization are unchanged. EA uses seedA; EB and both F
bases use seedB with separate side/factor addresses. Fresh B per mining job
therefore refreshes both seeds. The old emulation harness's fixed-key copied
noise helper was distribution-only evidence; B9 refreshes it to compile the
real noise module. This changes benchmark draws without changing their law.

## Plain proof and pool/gateway wire format

`PlainProofV4` adds `ancestor_chain`. Its canonical bytes come from
`PlainProofV4::to_bytes`, using strict fixed-int bincode, with the job encoded
as a byte string and the chain encoded as a byte string of concatenated
108-byte headers. Values/scales use Pearl's variable-chunk Merkle codec;
v3's chunk-1024 serialization is not interchangeable. `from_bytes` rejects
trailing bytes and chains over 324 bytes. `parse_proof` authenticates ancestry
before shape/opening checks.

Source: `zk-pow/src/api/fp8/plain_proof.rs`. The gateway still receives base64
plain-proof bytes and selects `PlainProofV4` by certificate version. Pool Go
bindings add `verify_plain_proof_v4_ffi` with a 76-byte proposed header and an
optional share nbits. The existing v1–v3 entry point is not the v4 verifier.

Gateway jobs now carry `ancestor_headers`, base64 complete headers, parent
first; node templates expose `ancestorheaders` as hex. Source:
`miner/pearl-gateway/src/pearl_gateway/comm/dataclasses.py`,
`node/btcjson/chainsvrresults.go`, and `node/mining/mining.go`.
Public pools' v4 notify transport for these headers is not established by the
old v3 pool research. A v4 notify lacking authenticated ancestor data cannot
be made into a valid new-head job from its 76-byte proposed header alone.

## Certificate and ZK statement

Dense public data grows from **212 to 244 bytes**, due to the extra 32 bytes
in sigma_d. Always use `PublicParams::to_bytes/from_bytes`; some upstream
module comments describe plane roots while the wire carries their folded
operand digests. Do not derive offsets from those prose comments.

The node's v4 certificate remains hash + length-prefixed public data +
length-prefixed proof + ancestor count + intermediate headers. The maximum
intermediate count changes from 2 to 3; zero now means the selected ancestor
is the parent (depth 1). The chain is outside `ProofCommitment` and is
authenticated through `prev_block`. ZK public digest/AIR inputs and fixture
proofs were updated for the 108-byte ancestor. Old verifier cache/proof bytes
must not be assumed compatible.

Source: `node/wire/certificate_v4.go`, `node/zkpow/verify.go`,
`zk-pow/bindings/go/src/verify.rs`, `api/fp8/zk.rs`, and
`circuit/fp8/blake3_stark/stark.rs`.

## Validation

Source comparison and an independent read-only review found no premise-breaking
change. The refreshed emulation oracle compiles the upstream noise, transcript,
public-parameter, and header helpers as well as the arithmetic/policy modules:
**98 tests passed, zero failed or ignored** (`b9_v0_oracle_tests.txt`).

The pinned upstream `zk-pow` library suite was run in two disjoint groups with
two Rayon threads and one test thread: the `fp8` filter passed **331 tests**, with
four existing upstream ignores; the complementary `--skip fp8` run passed
**105 tests**, with two existing upstream ignores. Together this covers all
442 listed tests: **436 passed, zero failed, six upstream-ignored**. The ignored
tests were not newly disabled by B9. Commands and results are in
`b9_v0_upstream_fp8_tests_release_serial.txt` and
`b9_v0_upstream_non_fp8_tests_release_serial.txt`.

The derived node build also passed its targeted certificate-v4 wire, fork
activation, required-version template, and verifier tests (`b9_v4_build.txt`).
Those checks establish V0's source/protocol baseline; they do not constitute
production GPU admission. Historical 107,282,432-cell prototype evidence is
not a B9 production G3 pass. The separate B9 gate uses fresh V1 CPU references
and the production library.
